## 6. Deviations and test notes

1. **Edits outside the round-1 allowlists.** My task allowed small cross-layer fixes, and I made two of them:
   * `theme.js` is GE1a's.
   * `catalog-data.json` is nobody's in round 1 and R2-D's in round 2.
   * I also refreshed GE1b's `tests/build/r1-debug` so that it matches the tree.
2. **C8.** `run-tests.sh` takes `$G/.heavy.lock` itself, so I used GE1b's wrapper-lock recipe. The real lock was verified free with `flock -n` just before each run. `run.sh` ran with `HEAVY_LOCK=.rt/cross/inner.lock` under heavy.sh, which held the real lock.
3. **ge1a-switch "en: Start opened 0.1 s after a rename is en in every frame from 1 s after opening on" is timing-dependent.**
   * In run 1 the host catalogue's Dutch tile names were still in the last recorded DOM frame (560 ms).
   * The recorder was read before a clean frame came, so `cleanFromMs` was null. The settle check that follows passed after 0.43 s.
   * In run 2 the last dirty frame was at 386 ms and the check passed (61/61). GE1a's own run had 326 ms.
   * Cause: the catalogue's 150 ms language poll plus a full settings read through `files::Context::language` (R2-C/R2-D).
4. **example.py's "en: GNOME app names English (C6 runtime rewrite)"** reads `app_names()` immediately after an in-place rewrite. GNOME needs 4.4-7.2 s (cross-r1, ge1c `c6_runtime`), so this check can only pass by luck. It should poll for 12 s, as `ge1c-extension.py` does.
5. **Notes on my scenario.**
   * The F step (fallback bar to Dutch) shows "Win11 File Explorer" on the pinned button while the panel is down. That is by design: win11-panel is the only C6 writer, and its restart repairs the entries.
   * Third-party pins show GNOME-locale names ("Settings" for GNOME's own Settings) in both languages.
