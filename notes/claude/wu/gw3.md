## 6. Deviations from the design and contracts

1. **Key names.** Row-state keys are `rsPendingDownload … rsFailed` (§3.3's `downloading`, `installing`,
   `restartRequired`-like names collide with the hero keys); `checking` keeps its old key (§3.2 `checkingFor`).
   `securityTag` is "Beveiligingsupdate" / "Security update" without the trailing " · " (joined in code).
2. **Five keys the design has no text for:** `relRunningNoVer` (releaseRunning without a version), `offlineDescNoWhen`
   (offline without `checkedAt`), and `rebootQ`/`rebootBody`/`reboot` for the page's own restart confirm when no
   panel takes the command (§3.2 asks for it); these three copy shell/power.js's rebootTitle/rebootBody/reboot.
3. **Glossary:** "Opnieuw proberen → Retry" (§8) is not added: 8 existing UI pairs say "Try again" and would become
   round-3 errors; update.js uses "Retry" anyway. `checking`'s en "Checking for updates…" carries a
   `glossary-ok: Controleren op updates` comment (the -ing form).
4. **`unknownDesc` kept** for the fallback when `update.status` fails (an older host); `unsupported` uses
   `unsupportedDesc` (§3.2) and shows `error.message` only for `test_seam`. The no-PackageKit reason itself is not
   shown on the unsupported hero (the design's caption has no slot for it).
5. **Errors outside the error phase** (`cancelled`, `not_authorized`, `cannot_cancel`, `test_seam`, …) and immediate
   write refusals show as InfoBars, matched on `code` (C2): info for `cancelled`, error for `test_seam`, else warning.
   Retry in the error phase re-installs when rows remain and the code is not network/offline/check_failed, else
   re-checks.
6. **Technische details** is a full-width Expander under the hero (in the InfoBar area), not inside the hero text.
7. **Rows have no icon** (as in Windows); their progress bar and Retry exist in the DOM only while shown (a hidden
   element would be read and dumped). A failed row keeps a red bar at its last percentage (§3.1 `error:true`).
8. Hero buttons: Cancel is a standard button (the hero's one accent action otherwise); foreign disables installAll.
9. Mock: `system.updates` keeps 3 while H03's rows hold 19 packages (Home's block must not move; the host's §4.10
   delegation makes the numbers agree). The subpages' registry descriptions avoid "inst…" so the `shell.search`
   (q=inst) block stays unchanged.

## 7. Screenshot review (against Windows 11 24H2 Settings › Windows Update, from memory: no reference set here)

* **Layout** matches: page title, hero (glyph left, 20 px semibold title + secondary caption, one button right),
  the update list as stacked cards with 4 px gaps, a "Meer opties" header with chevron cards, then this project's
  backup/about groups. Spacing follows the other Settings pages (22 px between sections).
* **Hero glyph:** Windows draws the accent sync glyph with a status badge and no disc; here the design's 64 px disc
  (kept from the existing page) carries the state colour (green idle, accent, caution restart/unsupported) and the
  badges are Windows' green ✓ / red ✕ (black glyph on light badges in dark mode, like Windows). The checking ring is
  a dot in a still frame (it animates live); the turning glyph is frozen in shots.
* **Rows:** title + caption left, status right in secondary text, "Downloaden - 45%" with the 160 px bar under it,
  exactly Windows' row pattern; per design they are expanders (Windows' rows are not), so each has a chevron.
* **Buttons:** one accent action per state; "Alles downloaden en installeren" / "Download & install all" fit at
  1280 px; disabled accent is grey (H09/H26).
* **Meer opties:** Updategeschiedenis (history glyph), Geavanceerde opties (gear, description) like Windows' rows;
  no Pause, Insider or carbon footer (design). GW6's Prompt row will take Windows' "Get the latest updates" place.
* **English widths:** at 1280 px every text is on one line. At 800 px (content about 470 px) long hero titles wrap to
  two lines and the button wraps below; row statuses wrap under the title. The first narrow pass showed the
  wrapped status indented 42 px and right-aligned in a 160 px box; fixed with a container query in the update block
  (status left under the title, chevron at the end). No clipping or overflow in any en shot.
* **Dialogs** (H18, H21, R05) are ContentDialogs with the warning glyph; R05's changelog is monospace, links open
  through `apps.openUri` (https only).
